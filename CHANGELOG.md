## v1.1.1 — 2026-07-29

_iOS build 16 · Android versionCode 16 · **development build — not submitted to the stores**_

No user-facing changes. This version exists to carry tooling, CI and documentation work, and
deliberately has no store blocks.

### 🔧 Technical

- **Documentation-only CI skip** (`5778b61`) — lint, version check and builds are now skipped for
  changes confined to `README.md`, `CHANGELOG.md`, `LICENSE`, `docs/**` and `.github/skills/**`,
  so documentation can merge to `main` without a version bump.
- **Version increment enforcement** (`f1fee6e`) — `npm run test-version` now runs in CI on pull
  requests to `main`. Previously this lived only in `.husky/pre-commit`, which is bypassable with
  `--no-verify` and absent entirely for commits made through the GitHub web UI.
- **End-to-end test suite** — Playwright harness with fixtures covering navigation, settings and
  Wind Guru, plus iOS and Android platform-specific configurations.
- **Agent skills** — `dp-e2e-testing` (`5607f6b`) and `dp-release-notes` skills added under
  `.github/skills/`.
- **Android build fixes** — Gradle `lintVital` disabled via init script, Metaspace raised to 1g,
  and deprecated `android.enableR8` / `android.enableProguard` flags removed from CI.
- **Changelog restructure** — this file rewritten into a single consistent, machine-parseable
  format. Repaired the corrupted v1.0.10 heading, deduplicated v1.0.7, removed references to a
  deleted `RELEASE_NOTES_v1.0.8.md`, and fixed mojibake. Store notes now live here permanently
  instead of in a gitignored scratch file.

## v1.0.10 — 2025-09-08

_iOS build 14_

Store notes for this release were not captured at the time.

### ✨ Improvements

- **Humidity readings** (#28, `10a662f`) — humidity added to Soda Lake current conditions,
  displayed alongside temperature.
- **App information in Settings** (`1428c56`) — new section exposing version details and app
  metadata, plus a clearer wind threshold description.
- **Faster startup** — wind data now loads once instead of twice on launch; the unnecessary
  Android recovery system and the aggressive splash screen timeout were both removed.

### 🐛 Fixes

- **Android font scaling** (#24, `032a0ad`) — fixed Y-axis label clipping when the device font
  size is increased, so charts scale correctly with accessibility settings.
- **Wind direction accuracy** (#26, `89c6cab`) — "Direction %" in Recent Wind Analysis now shows
  actual data coverage rather than consistency. For example it reports 90.9% (10 of 11 readings
  include direction) instead of a misleading 99.4%.

### 🔧 Technical

- Added `directionCoverage` to the `WindAnalysis` interface; `analyzeRecentWindData` now
  computes both consistency and coverage. Direction consistency is retained for internal alarm
  logic.
- Added dynamic font scaling support to `CustomWindChart.tsx`.
- Fixed a race condition where `useSodaLakeWind` and `WindStationTab` both triggered loads; the
  hook now waits for the component instead of auto-loading.
- Simplified `AndroidSafeWrapper.tsx` (removed app state monitoring and the 30-second recovery
  timeout) and `_layout.tsx` splash screen management (removed the 5-second force timeout).
- Test coverage added for humidity data, font scaling and missing-direction scenarios.
- Merged as `d1850c0` (PR #29).

## v1.0.7 — 2025-06-24

_Branch: `patch/timestamps` → `main` · merged as `2a5033e` (PR #17)_

Store notes for this release were not captured at the time.

> **Note:** this version was recorded twice in the original changelog under two different
> branches and dates. The two entries have been consolidated here. See "Additional changes
> recorded under this version" below for the second entry's contents — its true version number
> was never recorded, so it is preserved rather than reassigned.

### ✨ Improvements

- **Simplified, reliable alarm system** — one wind speed threshold drives one decision. The
  complex prediction logic that caused inaccurate alerts is gone, replaced by a simple on/off
  alarm with current conditions shown directly.
- **Enhanced wind station monitoring** — transmission quality alerts when a station has antenna
  issues, at-a-glance data quality summaries, clear explanations for gaps in wind data, and
  better data freshness indicators.
- **Cleaner, faster interface** — streamlined navigation, faster loading, clearer error
  messages, and every screen focused on essential wind information.
- **Zero configuration required** — the OpenWeatherMap dependency and its API key requirement
  were removed. The app now works out of the box with automatic fallbacks across data sources.

### 🔧 Technical

- **Alarm system simplification** — removed the 6-factor MKI (Mountain Wave–Katabatic
  Interaction) analysis system, the `AlarmControlPanel.tsx` and `AlarmStatusCard.tsx`
  components, the `useDPAlarm.ts`, `useUnifiedAlarm.ts` and `useWindAlarmReducer.ts` hooks, and
  the `enhancedAlarmService.ts`, `backgroundAlarmTester.ts` and `mountainWaveAnalyzer.ts`
  services. Replaced by a single wind speed threshold with real-time monitoring.
- 12 components and 8 services removed; 22 files modified; documentation consolidated into 4
  core files.

### Additional changes recorded under this version

Originally filed as a second `Version 1.0.7` entry (branch `patch/remove-alarm`, dated
2025-06-28):

- **Smart prediction locking** — automatic prediction freeze at 11 PM with visual lock
  indicators.
- **Enhanced wind direction analysis** — improved calculations and chart rendering.
- **Simplified threshold management** — streamlined wind speed preference handling.
- Roughly 3,862 lines of complex alarm code removed for better stability.
